# HUB_RUNBOOK.md — rebuild the hub from nothing, and the road to no hub at all

Owner request 2026-11-02: "write the runbook … I don't like dependencies and
lost ties." Two parts:

- **Part A — make the hub disposable** (this week): if the droplet dies, a new
  one is serving trader / paper / shine again in ~1–2 hours, from GitHub + R2 +
  your password manager. Nothing important lives only on the box.
- **Part B — migrate off it fully** (phased plan): what can move to
  Cloudflare, in what order, and the one decision that makes "zero servers"
  possible.

### 3. Rebuild — new droplet to serving (target ≤ 2 h)

> Golden rule: **only one Schwab refresher may ever run.** If the old hub is
> still alive in any form, stop its `hub-schwab` container (or power it off)
> **before** step 3.8. Two refreshers invalidate each other's grant.

**3.1 Server.** DigitalOcean → Ubuntu 24.04, same region, ≥ the old size.
Note the new IPv4. Root SSH key from your password manager.

**3.2 Tailscale.** `curl -fsSL https://tailscale.com/install.sh | sh && tailscale up`
→ approve in the admin console; rename the machine `hub` (delete the dead
`hub` node first so the name is free).

**3.3 Code.**
```
git clone https://github.com/alwahedi-netizen/combo-trader /root/combo-trader
git clone -b claude/new-session-tsupmi https://github.com/alwahedi-netizen/combo-trader-tv /opt/logicon/combo-beta
git clone https://github.com/alwahedi-netizen/spx-0DTE-v1 /root/spx-paper-trader
```

**3.4 Secrets back in place** (from the password manager — never from chat):
`/opt/logicon/infra/.env` (chmod 600), `gate_secret` + `gate_credentials.json`
into `/opt/logicon/spx-paper-trader/` (chmod 600), the compose `.env`,
`/opt/logicon/infra/r2-backup.env` (or re-run `setup_r2_backup.sh`).

**3.5 Restore the databases BEFORE any app starts** (credentials from
`r2-backup.env`; `setup_litestream.sh` writes `/etc/default/litestream`):
```
sudo bash /root/combo-trader/deploy/setup_r2_backup.sh        # installs boto3 + env + timer
sudo bash /root/combo-trader/deploy/setup_litestream.sh        # installs litestream + creds
set -a; . /etc/default/litestream; set +a
for pair in "combo-trader-journal:/opt/logicon/combo-trader/logicon_journal.sqlite" \
            "combo-beta-journal:/opt/logicon/combo-beta/logicon_journal.sqlite" \
            "shine:/opt/logicon/combo-beta/shine/shine.sqlite" \
            "paper-labs:/opt/logicon/spx-paper-trader/data/labs/labs.sqlite"; do
  name=${pair%%:*}; db=${pair#*:}; mkdir -p "$(dirname "$db")"
  litestream restore -o "$db" "s3://logicon-backups/litestream/$name?endpoint=https://<ACCOUNT_ID>.r2.cloudflarestorage.com" \
    || echo "litestream restore failed for $name -> use the nightly: python3 /root/combo-trader/deploy/r2_backup.py --restore hub/<name>/latest.sqlite.gz <out.gz>"
done
chown 1000:1000 /opt/logicon/combo-trader/logicon_journal.sqlite    # prod journal is written by uid 1000 containers
```
Paper Lab CSV journals come with the `spx-0DTE-v1` clone (`data/`).

**3.6 Apps.**
- Trader prod: `cd /root/combo-trader/deploy && sudo bash setup_server.sh`
  (deps, ufw, Tailscale-only ports), then rsync to `/opt/logicon/combo-trader`
  and bring the docker stack up from the restored compose file
  (`docker compose up -d`) — `deploy/update.sh` is the reference for paths.
- Beta + Shine: `sudo bash /opt/logicon/combo-beta/deploy/hub/hub-beta-setup.sh`;
  Shine per `shine/PROJECT_SHINE.md` §7 (`shine.service` + override:
  `SHINE_PORT=8795`, `SHINE_HUB_BASE=http://127.0.0.1:5050`, `SHINE_USER`).
- Paper Lab + gate + auto-deploy (do NOT use `setup_sahmi.sh` — it installs
  the old Caddy front end, superseded by nginx):
  ```
  rsync -a --exclude .git /root/spx-paper-trader/ /opt/logicon/spx-paper-trader/
  python3 -m pip install -r /opt/logicon/spx-paper-trader/requirements.txt
  for s in logicon-paper logicon-gate; do
    sed "s/__LOGICON_USER__/root/" /opt/logicon/spx-paper-trader/deploy/$s.service > /etc/systemd/system/$s.service
  done
  systemctl daemon-reload && systemctl enable --now logicon-gate logicon-paper
  bash /root/spx-paper-trader/deploy/setup_autodeploy.sh        # hourly journal snapshots + test-gated deploys
  ```
  (`root` = today's owner of `/opt/logicon/spx-paper-trader`; check the
  inventory. No `gate_credentials.json`? `setup_sahmi_login.sh` re-enrolls.)
- IB (optional — read-only monitoring): `deploy/ib/README_IB.md`; first login
  needs the IBKR app 2FA approval.

**3.7 nginx.** `cd /root/spx-paper-trader/deploy && sudo bash setup_sahmi_home.sh`
(home + trader + paper + shine, all behind the gate). Restore the client-portal
site from its source (see inventory). `nginx -t && systemctl reload nginx`.

**3.8 Schwab.** ONLY after §3.10's DNS cutover (until then
trader.sahmi.ae still resolves to the dead box) — or over the tailnet at
`http://hub:8445/reauth`. Start the Schwab backend, open the reauth page
→ Schwab login → paste the redirect URL. Countdown shows 7 days.

**3.9 Backups + auto-deploy on.**
```
git -C /root/combo-trader pull   # the script must be current: it auto-creates the svc-uid1000 passwd entry
sudo bash /root/combo-trader/deploy/setup_litestream_journals.sh --force   # per-owner streaming
sudo cp /root/combo-trader/deploy/logicon-autoupdate.{service,timer} /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now logicon-autoupdate.timer
```

**3.10 Cut traffic over.** Cloudflare → DNS `sahmi.ae`: point `@`, `trader`,
`paper`, `shine` A records to the new IPv4 (stay **Proxied**; SSL stays
**Flexible**). The worker needs no change — it reaches the origin by name.

### 4. Verify (all must pass)
```
for h in sahmi.ae www.sahmi.ae trader.sahmi.ae paper.sahmi.ae shine.sahmi.ae; do curl -sI https://$h/ | grep -iE '^HTTP|server-timing'; done   # 302 + edge-auth (EDGE only — these pass even with the hub dead)
curl -s https://paper.sahmi.ae/__cf/version | head -c 200                                            # router healthy
systemctl --no-pager status logicon-paper logicon-gate logicon-beta shine 'litestream-uid*' | grep -E '●|Active'
docker ps --format '{{.Names}} {{.Status}}'                                                         # hub-platform/schwab/gex Up
journalctl -u 'litestream-uid*' -n 30 --no-pager | grep -c 'wal segment written'                     # > 0
```
Then sign in on the website — THIS is what verifies the rebuilt hub (the
curls above only prove the edge): trader desk loads, `/reauth` shows 7 days,
Paper Lab overview shows the same NAVs as before the outage, Shine shows its
lanes.

### 5. Rollback / old box
Until §4 passes, the old droplet (if alive) stays powered **off** but not
destroyed. DNS back to the old IP undoes the cutover. Destroy the old droplet
only after a week of clean nightly backups from the new one.

### 6. Rehearsal (turns this draft into a procedure)
Once, on a throwaway droplet, with DNS **unchanged** and Schwab **not**
started (so the one-grant rule is never at risk): §3.1–3.7 + §3.5 restores,
then check the apps over Tailscale. Time it, fix every step that didn't work
as written, delete the droplet. Repeat yearly.

## Part B — the road to no hub

### 7. What decides it
Everything except two items could run on Cloudflare (Workers + D1 + Cron +
Containers). The two:

1. **IB gateway** — needs a long-lived Java process with IBKR 2FA.
   **DECIDED (owner, 2026-11-02): "migrate IB monitor, it's just monitor."**
   Target: a Cloudflare **Container** running IB Gateway + the dashboard.
   Caveat that makes it LAST (B7): a container restart may require an IBKR
   2FA re-approval on the owner's phone; if that proves too noisy in
   practice, fallback = tiny VM or drop (owner re-decides then).
2. **The Schwab grant** — today a long-running process refreshes the token.
   It does not need to be: access tokens last 30 min and are refreshed from a
   7-day refresh token. A **Cron Worker every 25 min** + the token in a
   **Durable Object** (one single writer = the "ONE grant" rule enforced by
   design) replaces it; the weekly `/reauth` becomes a Worker page.
   **DECIDED (owner, 2026-11-02): approved** — estate rule amended in
   combo-trader-tv CLAUDE.md, effective only when B4 ships. NOTE: the
   refresher itself can never parallel-run (two refreshers invalidate each
   other) — B4's refresher is a hard cutover; only the quote/order proxy
   parallel-runs.
